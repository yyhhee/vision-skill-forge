# 技能规则工作台：整项总览与定位编辑

2026-10-16，基于原版 `vision_skill`，回退基线 `777d321`。

## 解决的功能问题

03 已有条件、时间、编排组、最终判定、业务输出和触发编辑器，但入口分散。用户需要先看到技能由什么组成，再找到要修改的对象，而不是理解节点 ID 或另建一套规则。

新增“整项技能总览”放在现有编辑区上方，不替换成熟编辑器。总览分成五个配置层次：

- 分支条件：实际条件公式、附加分支计时、有效期、停用状态。
- 分支编排：成员来源、嵌套组名称、基础关系、关联范围和顺序依赖。
- 最终判定：当前媒体使用的来源及 AND / OR / 至少 N 项。
- 业务输出：结果类型和真实来源；按当前图片/视频过滤。
- 触发策略：当前触发模式和冷却时间。

这些是配置层次，不是新增的串行执行顺序。总览是摘要，完整参数仍由对应编辑器展示。

## 用户操作

1. 生成或加载技能，进入 03。
2. 查看总览，搜索“要编辑哪一项”：分支、具体条件、编排组、最终判定、输出或触发策略。
3. 点击“定位到编辑区”。系统打开对应标签并装载选中的对象；同名对象用编号区分。
4. 在原有表单编辑并保存到草稿。总览自动更新。
5. 点击现有“应用修改，更新运行版本”，通过校验后才能执行修改后的规则。

定位不是保存，也不是应用。切换前提示保存当前表单；本次未新增全局未保存表单拦截。原有编辑入口仍可使用。

## 技术边界

- `ui/v2/controllers/workbench.py`：只读投影、稳定导航地址、目标存在性检查和复用现有控制器的表单更新。
- `ui/v2/bindings/workbench.py`：草稿/媒体变化刷新总览，点击定位刷新目标编辑区。
- `ui/v2/pages/review.py`：组件与现有标签的稳定 ID。
- 不新建技能存储、草稿状态、编译器、执行器或类别规则。
- 导航回调不输出 `editor_document`，不发布运行包，不调用模型。输出表单仍使用原有确定性类型检查。
- 当前媒体内解析导航地址；删除后或跨媒体地址拒绝定位，不悄悄选择其它对象。
- 从导入包到自然语言编排使用同一读取路径；名称、短语、说明均转义后展示。
- 只刷新目标表单，不重载其它标签的未保存表单；原有依赖字段刷新保持不变。
