# 原版 V2：统一配置修改与生效

2026-10-16。在原版目录实施，不更改检测算法、模型请求规则或 P01–P13 预置技能内容。

## 用户操作

1. 在 **03 审核**选择条件、分支、时间、逻辑、业务输出或触发策略，修改对应卡片。
2. 点击卡片的“保存……到草稿”。此时 **03 和 04 同时显示“有未应用修改”**；当前运行版本保持不变，暂不能运行。
3. 点击 **“应用修改，更新运行版本”**。本页顶部、业务编辑区底部和专业模式中的同名按钮调用同一个校验/编译入口，不是三套生效机制。
4. 成功后，两页显示 **“当前运行版本：Rn”**；04 使用本次生成的运行包。若缺少必需标注，仍需先完成 02。
5. 应用失败时保留草稿，上一运行包不被替换，修正错误后再次应用。

仅在输入框中打字、尚未点击卡片保存，不算已保存的草稿修改。页面有明确的“保存到草稿 → 应用修改”提示，不宣称自动保存未提交表单。

## 状态与边界

| 状态 | 运行包 | 页面与运行行为 |
|---|---|---|
| 已加载/已应用 | 与版本记录一致 | 显示当前 Rn；仍执行既有媒体、资源及结构校验 |
| 有未应用修改 | 上一运行包仍保留 | 显示旧 Rn 不变；禁用运行按钮，执行服务也拒绝运行 |
| 应用失败 | 不替换上一包 | 草稿继续待修改，不递增运行修订号 |
| 应用成功但缺标注 | 新包已生成 | 提示先完成 02；原有标注前置检查继续生效 |
| 配置/运行包不一致 | 不认可为当前版本 | 显示版本不一致，要求重新读取/应用 |

Rn 是编辑工作区的运行修订号，不是技能持久化版本 `/vN`、Git 提交号或全局版本历史。显式重新加载技能会以所选运行包建立工作区基线；“保存为新版本”仍使用原有持久化机制。

02 标注以及既有缩放、抽帧、切片、提示词等执行参数卡仍保留“点击应用立即更新”的兼容行为：它们更新前经过同一当前版本检查，之后刷新版本记录。存在未应用业务草稿时会拒绝覆盖，要求先应用草稿。此轮没有重做全部执行卡表单或增加第二套技能格式。

## 实现边界

- `application/v2/configuration.py`：唯一的草稿暂存、发布与当前版本检查服务，不依赖 Gradio。
- 版本记录放入现有编辑文档的 `validation_report.configuration_publication`：配置摘要、运行包摘要、运行修订号；没有第二份可编辑技能状态。
- 配置摘要覆盖模板、场景配置、活动场景与用户覆盖，不包括校验报告和派生产物。即使手工 JSON 修改遗漏 dirty 标志，摘要不同也会判为未应用。
- `ui/v2/controllers/configuration.py`：包装已有编辑命令，统一保存草稿；原方法签名、返回组件与业务语义保持兼容。
- `ui/v2/controllers/editor.py`：唯一发布入口调用原 `EditorService.apply`。只有校验成功且无待确认项才返回新运行包；刷新不得给脏草稿重新挂上旧运行包。
- `ui/v2/bindings/activation.py`：03/04 共用状态展示和运行按钮可用性。
- `application/v2/execution.py`：携带编辑文档的运行请求在调用模型前检查当前版本，不只依赖前端按钮。
- 撤销、重做、恢复默认同样产生草稿，不回退当前运行修订号。
- 显式加载预置/已保存技能重新建立编辑文档，避免同 ID 缓存草稿覆盖用户选中的包。

本次不引入跨会话版本库、多人并发事务或自动表单保存；无编辑文档的历史程序调用保留兼容入口。
