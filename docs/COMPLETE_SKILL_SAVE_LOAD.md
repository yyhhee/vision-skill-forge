# 完整技能保存与加载修复

## 行为

- “保存为独立版本”保存同一版本的运行包和完整编辑文档。随后从 01“已保存技能”或 05 资产加载，03 优先恢复原文档，不再从运行包重新猜测业务结构。
- 保留条件树、稳定条件/分支/编排组 ID、组的嵌套与依赖、时间策略、最终判定、业务输出、展示偏好、人工覆盖以及场景配置。
- 支持另存名称、技能标识、自定义资产目录和反复保存。运行包、文档、内嵌运行包使用一致的保存版本及身份；加载同一技能的不同版本会替换缓存，不复用上一版本的组结构。
- 只允许保存已经应用、且与当前运行包一致的文档。加载后重新记录一致的运行版本指纹，不将改名/资产版本变化误判为未应用修改，也不重新调用 LLM 或视觉模型。
- 当前运行包与缓存文档完全一致时，打开编辑器不会凭空新增默认场景配置或重新投影已保存标注。

操作方式不变：保存卡片修改到草稿 → 应用修改，更新运行版本 → 保存为独立版本 → 选择版本并加载。

## 原因与修复位置

1. 原 `SkillService.load_saved_skill()` 不读取 `skill_documents`，而是无条件调用 `build_editor_document(package)`。该导入只能表达执行图，无法恢复完整业务编排。
2. 原保存逻辑让两个 Store 各自计数。已有单独运行包或文档时，配对文件可能不在同一个版本号。
3. 原另存更新文档模板名称/标识，但内嵌运行包和运行版本指纹仍指向原元数据。

实现集中在 `application/v2/skill_assets.py`；沿用既有 PackageStore、SkillDocumentStore 和配置生效服务，不增加新的技能格式、插件或数据库。

- 版本号按两个目录已使用版本的并集递增，避免覆盖文档-only 的历史尝试。
- Store 支持显式版本号并排他创建文件，不覆盖已有版本。
- 先写完整文档，再写作为版本列表入口的运行包。普通写入失败只清理本次新建文档，不触碰原版本。当前应用进程内的并行保存串行分配版本；不宣称跨进程/掉电的双文件原子事务。进程中断遗留的文档-only 版本会被后续保存跳过。
- 加载核对所选路径与运行包身份/版本、对应文档身份/版本、内嵌执行内容、未应用状态及运行版本指纹。文档存在但损坏/错配时明确失败，不静默丢弃文档，也不覆盖当前缓存。
- 历史保存只改了模板身份、内嵌包元数据未同步的情况，可在执行内容一致、还原原元数据后的版本指纹校验通过时安全归一化。不借此接受执行内容差异。
- 原有 3.0/3.1 文档仍走既有 Schema 迁移；安全元数据投影发生在新加载基线建立之前。

## 历史限制

如果所选版本没有对应编辑文档，仍可导入运行包，并提示“旧版本只有运行包”。运行包中未记录的原始括号组、业务分支拆分等信息无法无损逆推；本次不会虚构这些结构或猜测另一个版本的文档。用户保存的新版本包含完整编辑文档，后续可继续编辑与复用。
