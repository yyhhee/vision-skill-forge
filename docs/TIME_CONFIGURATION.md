# 时间配置：明确作用对象，避免重复计时

## 用户操作

进入 **03 审核 → 事件规则编辑 → 条件分支 → 时间设置**。

1. 选择本次修改对象：已有计时条件，或当前整个分支。存在已有条件计时时，默认选中它，而不是引导新增分支计时。
2. 面板显示当前分支已有计时、秒数、输入条件名称。不会把“分支不额外等待”解释成“分支内没有计时”。
3. 按方式填写必要参数：

| 方式 | 必填字段 | 其它字段 |
| --- | --- | --- |
| 不额外等待 | 无 | 没有已有计时条件的分支可选择成立后是否保持，以及保持秒数 |
| 连续满足 | 连续秒数 | 允许中断、身份范围；分支还可选择结果产生方式 |
| 窗口内累计满足 | 观察窗口、累计秒数 | 身份范围；分支结果产生方式 |
| 窗口内满足时间占比 | 观察窗口、占比 | 身份范围；分支结果产生方式 |

4. 保存到草稿，再点击 **应用修改，更新运行版本**。保存草稿不改变当前运行版本。

身份范围始终针对所选条件的输入或分支组合结果，不是另一套检测目标。目标/轨迹/目标对/区域身份必须来自上游证据；执行层不会猜测缺失身份，也不会拼接不同身份的时间。

## 防重复计时

- 编辑已有计时条件：按稳定条件 ID 原位修改，不添加新步骤。
- 编辑分支计时：替换此分支原有的单条策略，重复保存不追加。
- 分支内已有计时条件时，额外的分支计时必须勾选确认，明确表达“条件计时完成后，整个分支还要再计时”。不额外等待时隐藏该确认框。
- 计时已产生事件区间时，不在普通面板叠加“成立后保持”计时。复杂策略仍保留高级入口。
- 多条策略、非当前分支目标引用、特殊时间模式不能被简化面板整体覆盖；按区域分别配置的历史阈值也不会被统一参数覆盖。
- 图片不能设置持续、累计、窗口或时间保持；隐藏字段的旧值不参与当前方式的保存。

## 实现范围与兼容性

- 新控制器：`ui/v2/controllers/time_configuration.py`。沿用原有业务条件、`TemporalQualifierSpec` 和统一草稿事务，无新增 DSL、运行旁路或场景特判。
- 已有业务 `temporal.persist` 条件统一接入；新增单条件时间约束仍使用资产库中的该能力，选择类型兼容的条件输入。普通面板不是给任意实体输出直接贴时间修饰符。
- 资产库补充窗口与比例参数。累计/占比确定性编译为现有 `temporal.qualify@1.0`，不再忽略选中的窗口方式。未指定新模式的连续计时保留原 `temporal.persist@1.0` 路径。
- 历史导入的持续节点只提供其真实支持的“不额外等待/连续”选项；按节点原参数映射更新秒数、中断和身份范围，不暗中迁移算子。
- 条件与分支计时独立修改，其他分支和其他策略保持不变。
- 连续/累计必须大于零；累计不能超过窗口；窗口大于零；比例 0–100%；禁止负中断或非有限数值。已有条件选择不额外等待时写入 0 秒并保留原事件类型，而非删除节点或改变下游契约。
