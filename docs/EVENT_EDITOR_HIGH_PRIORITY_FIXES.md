# 事件编辑四项高优先级修复

2026-10-16。在原版 `vision_skill` 的 `70c3b04` 基线上修复，不重做页面或引入第二套编排内核。

## 修复行为

1. **连续计时**：0 秒容忍不再要求相邻观测具有相同时间戳。优先使用视频抽帧得到的实际采样时间线，正常相邻样本可累计；遗漏采样、明确的 false 仍能切断连续段。没有媒体上下文的旧程序调用使用输入观测时间线，不凭空生成未观测时段。
2. **时间身份**：分支时间将 global/object/track/pair/region 显式写入 `temporal.qualify` 参数。非全局分支的实体投影与 AND/OR 保留身份键，不先归约成全局真假。目标、轨迹、区域计数、目标对及布尔逻辑携带相应身份元数据；运行前后不凭一个不透明 key 猜其类型。来源缺少所选身份时明确报错，而不是静默当作全局或同一主体。
3. **编排组引用**：更新同一成员组保留 pattern_id；底层编辑 API 另支持指定 pattern_id 后修改成员。父组、最终判定和输出引用不因参数修改失效。“不组合”只移除选中的组；有依赖时拒绝删除并列出引用方，多组且未选择时不批量清空。直接/间接循环引用会被拒绝。
4. **恢复默认**：业务区和专业模式复用同一个恢复回调，恢复结果经过统一 stage，保留当前运行修订号，并进入撤销历史。恢复后必须再次应用；重新应用时 Rn 继续递增。

## 兼容与边界

- 没有改动预置 JSON、检测类别、模型提示词、推理批处理或场景专项规则。
- 已有 `temporal.qualify` 节点未写 identity_scope 时默认为 `source`，沿用原有上游键。新编译的分支资格节点使用显式身份。时间资格算子及身份参数仍由现有 Registry 定义。
- 不将图像检测框的临时 ID 自动视为跨帧轨迹。需要“同一轨迹”时，必须先有实际轨迹身份；缺失身份的来源会报错，需要用户调整来源或增加现有跟踪能力。
- 区域身份需要来源提供 region_id，例如逐区域计数/测量或明确的区域条件；不能把多个区域的联合布尔结果猜成某一个区域。
- 本轮没有改动审核中的其它次优先项：事件周期触发语义、同时有效与曾经完成的 UI 区分、自由文本业务输出和完整时序界面重设计，仍属后续工作。
