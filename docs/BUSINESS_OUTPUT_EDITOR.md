# 业务输出受控编辑

## 用户操作

在 **03 审核 → 业务输出** 中：

1. 在“编辑哪项输出”中选择已有输出，或点击“新增业务输出”。
2. 修改输出名称，在“结果来源”中选择业务名称。选项标明所属分支、条件或最终判定，以及图片/视频范围，不要求填写技术 ID。
3. 在“希望看到的结果”中选择兼容类型，如数量、目标列表、是否满足、事件列表或标注媒体。更换来源时，不兼容的旧类型会清空，需重新选择。
4. 按需填写单位，选择证据保存、结果保存和概览显示策略。
5. 点击“保存业务输出到草稿”，再点击“应用修改，更新运行版本”。只填写表单但未保存，不会进入草稿；保存草稿但未应用，不会改变运行版本。

上方表格是已保存草稿的只读概览，不再通过自由文本编辑来源和结果类型。同名输出通过可见序号区分，内部仍使用稳定引用。

## 通用实现

- `core/business_output_editor.py` 读取现有确定性编译结果，获取真实来源类型；不按案例、对象名或预置编号判断兼容性，不调用模型。
- `CompiledValue.result_node()` 由输出编辑器和正式编译共同使用，选择同一个投影节点。数量条件可引用其测量结果，不将所有条件/分支误当作布尔值。
- `projection_accepts_type()` 和 `contract_type_and_shape()` 与运行时共享，避免界面、编译和结果展示各自维护不一致的类型规则。
- 条件、分支、编排组、最终判定及标准输出按业务名称提供受控选项。跨媒体公共来源仅提供各变体均兼容的类型；来源不存在或编译失败时显示原因，不悄悄替换来源。
- 编辑单项保留稳定输出 ID，其它输出不重建；不修改绑定时保留未暴露的分组、标签、投影参数和展示配置。绑定改变时清除旧的派生输出绑定，由正式编译重新生成。
- 删除保护最后一个输出和仍被最终判定或其它输出引用的项，不自动把最终判定改绑到其它项；保存时再次校验来源、类型和循环依赖。
- 保存、删除均接入现有统一草稿事务与运行版本生效门禁，不增加第二套文档状态。
