# 16个画面状态合同

## 读取与执行约定

screen-states.json是逐页捕获入口：视口、路由、fixtureId、选中项、抽屉、展开项和滚动状态都必须一致。fixture中的时钟固定在2026-10-17 10:26，只用于复现原图；不是实际日期。

每例独立恢复种子，不依赖上例操作；普通用户操作则共享同一文档。路由中的调试状态只用于本地演示与测试，不能被当作生产执行接口。
下表的固定数据是前端演示合同，不是从原项目导出的真实规则或检测结果。原图矛盾之处已按DECISIONS登记修正。

公用：浅色；DPR1；缩放100%；滚动归零；无悬停、无焦点环、无动画；字体加载后截图。功能测试另行覆盖键盘焦点，不能为了截图取消可访问性支持。

## 关键跨页状态，不允许各页自行硬编码

1. R3中颜色阈值20%；当前草稿10%。这是明确演示差异，用于证明保存草稿没有影响运行快照。
2. 06的5秒只是该截图用例的未保存表单，不能污染04/09/12。07是独立顺序配置示例，不擅自加入区域告警规则。
3. 10和11是同一runId的不同阶段；11的事件、证据、主体、时间和R3对应，不能来自当前草稿。
4. 09的30帧为脚本演示轴采样点0–29秒；没有真实视频时不得展示“已读取真实FPS/真实mp4”。
   这些视频配置示例使用video_demo文档意图、poster_only预览载体；普通图片模式不可借此启用视频顺序。真实播放始终未提供。
5. 02与04文字表达一致；字数由输入计算；原图内的错误计数不保留。
6. 自定义条件的A/B/C编号是展示顺序，不是持久化身份。引用使用稳定内部ID，但用户选择时只见名称和上下文。

## 没有原图但必须可用的状态

按D-13复用现有对话框/抽屉风格，不再生成另一套页面：

- 表单未保存离开：保存／放弃／继续编辑；保存校验失败仍停留。
- 草稿尚未应用：明确显示有未应用修改、当前运行R3；校验并应用后才能出现R4。
- 区域/条件/组被引用时删除：列出影响，允许取消；不得静默更换来源。
- 无媒体、媒体解码失败、无结果、搜索无匹配、导入JSON错误、浏览器存储不可用。
- 模拟运行取消/失败；凭证未配置/模拟连接失败；插件依赖缺失/停用/版本不兼容。
- 从历史结果进入编辑：查看R3快照／编辑当前草稿，明确区分。
