# 能力管理：纯前端清单规范

入口：`/settings/capabilities`。当前管理本前端已实现配置所需的能力，不代表已迁移旧版全部执行原子。所有条目可启停；内置不可删除，用户自定义清单删除前检查引用。不会安装或执行 JS/Python，不连接模型。

## 导入文件

UTF-8 JSON，最多128 KB。页面先校验和预览，再由用户确认安装；默认停用。重复标识不覆盖原能力。支持以下完整声明，不接受额外字段：

```json
{
  "format": "vsf-capability-manifest",
  "schemaVersion": 1,
  "id": "my-region-check",
  "name": "我的区域检查",
  "kind": "template",
  "description": "组合区域归属与数量判断的能力声明。",
  "input": "目标与标注区域",
  "output": "区域判断结果",
  "parameters": ["区域", "数量"],
  "uses": ["region-membership", "count"],
  "plannerHint": "当用户要求区域内数量判断时，明确目标来源与数量条件。"
}
```

- `id`：小写字母开头，小写字母/数字/横线，1–64字；不可占用已有能力标识。
- `kind`：`business`业务能力、`execution`执行能力、`template`组合模板。当前三种均只安装元数据，不能凭声明获得执行器。
- `name`：1–80字。描述、输入、输出、编排说明各1–1500字。
- `parameters`：最多32个可读参数名称，各1–80字；不是可执行表达式或参数编辑器的Schema。
- `uses`：最多32个不重复的已安装能力标识。禁止缺失依赖、自引用和循环依赖。启用时要求所有传递依赖已启用，不自动联动修改。
- `plannerHint`：作为数据查看的能力说明，未发送给LLM；接入后也不能覆盖系统约束。

内置标识：`detect`、`color-review`、`instance-dedup`、`temporal-composition`、`color-fraction`、`same-subject`、`region-membership`、`count`、`time-window`。界面默认展示主要能力，基础依赖可展开查看和管理。`custom-patrol`是默认停用的演示自定义清单，可以删除；不会假称其已可执行。

## 可用状态与技能正确性分开

`SkillDocument.capabilityRefs?: string[]`可保留完整技能显式依赖；已有条件、时间、区域和去重配置通过类型映射确定所需内置能力，并展开依赖闭包。不以对象名称、类别或自然语言关键词猜业务。未知条件类型、缺失能力、停用能力和只有清单的自定义能力均阻止应用/新运行/继续运行；自动推进也先检查。已有结构校验、完整技能保存/导入、历史结果查看不依赖当前启停状态，不把停用误判成文件损坏。

引用检查读取实际草稿、已应用R、保存V和未结束运行快照，并检查其它能力的传递依赖；任一相关缓存不可读则无法安全删除/停用，不静默当成无引用。停用允许用户明确确认影响；删除只允许未被引用的用户清单。历史结果不重写、不删除。

## 存储与边界

独立键`vsf-frontend-capabilities-v1`，包括Schema、状态覆盖和自定义清单。写前比较原值；配额失败不报告成功；缓存损坏保留原文并阻断写入。其它标签冲突需显式重新载入，安装预览不丢失。`fixture=capabilities`只操作当前页内存，不写正常数据；其它截图fixture同样不受正常启停状态影响。

模型接入配置、技能草稿、运行R、保存V、历史结果仍分别存储。没有后端安装、动态执行器注册、LLM接入或自动模型路由；需要这些能力时应另行设计和实现，不使用本清单冒充。
